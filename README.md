# NekoChat

語喵的 LINE 群聊元件，透過 [LINE.js 機器人 API `/api/ws`](https://github.com/JS-PACKAGE/LINE.js#機器人-apiapiws) 連線，不修改 LINE.js 本體，也不是 LINE Messaging API webhook。

## 啟動

需要 Node.js ≥ 22、npm、已登入的 LINE.js，以及 OpenAI 或 Anthropic 的 API key（至少一個；兩個都設定時一個主要、一個備用）。應用程式與測試皆使用 strict TypeScript，編譯後由 Node.js 執行。`start.sh` 會自動安裝缺少的依賴；若要手動安裝：

```sh
npm ci --include=dev --ignore-scripts
```

本機已有 `config.yaml` 時直接編輯，不要覆蓋。全新安裝且尚無設定檔時，從 `config.example.yaml` 複製為 `config.yaml` 並將檔案權限設為 `600`。啟動與檢查預設皆讀取 `config.yaml`。

1. 在 LINE.js 的 `config.yaml` 啟用 `api.enabled: true`，將要授權的聊天室 ID 加入 `api.chats`，重啟 LINE.js。
2. 在 **LINE.js 專案目錄**執行 `npm run cli -- token`，取得僅顯示一次的 Bot Token。
3. 填入 NekoChat `config.yaml` 的 `line.token` 與 `line.chats`。這是 LINE.js Token，**不是** OpenAI 或 Claude API key。要使用 OpenAI 時加入 `openai` 段並填入 `openai.apiKey`；範本則不含任何金鑰。
4. 啟動：

```sh
./start.sh --check
./start.sh
```

`start.sh` 可從任意工作目錄執行，會先檢查 Node.js ≥ 22、執行依賴及 TypeScript 工具鏈；缺少或無法載入時自動執行 `npm ci --include=dev --ignore-scripts`，依照 lockfile 重建 `node_modules`，不執行套件安裝腳本，也不會覆蓋設定。即使 `NODE_ENV=production` 也會安裝編譯所需的開發依賴。每次啟動先編譯至 `dist/`；安裝、依賴載入或編譯失敗時停止，不啟動舊產物。`--check` 只驗證本機設定並顯示主要與備用供應商，不連線 LINE、OpenAI 或 Anthropic，但缺少依賴時仍會觸發安裝，可能連線 npm registry。指定其他設定檔可使用 `./start.sh --config /path/to/config.yaml`，相對設定路徑以專案目錄為基準；按 Ctrl+C 停止。修改設定後須重啟。`npm start`、`npm run check` 也會先編譯，但不會自動安裝依賴。

`line.chats` 不得留空；只有同時在 LINE.js 與 NekoChat 白名單內的聊天室會被處理。尚未接話時，引用回覆語喵、LINE @ 標記語喵，或文字包含「語喵」才會送交模型判斷；這些條件不保證回覆。只有明確向語喵提問、招呼、邀請聊天或回應語喵時才接話；成員彼此問答、只是談論語喵或對象不明時保持安靜。請確認群組成員同意將訊息送往 OpenAI 或 Anthropic（設定了備用時兩者都可能收到）；建議先用測試群與次要 LINE 帳號驗證。

## 設定

| 欄位 | 用途 |
| --- | --- |
| `line.url` | 預設 `ws://127.0.0.1:3789/api/ws`；遠端連線要求 `wss://` |
| `line.token` | LINE.js 產生的 Bearer Token |
| `line.chats` | 要回覆的聊天室 ID 陣列 |
| `line.ownMemberIds` | 選填，聊天室 ID 對應自己在社群的成員 ID；未填時以 `chat:admins:get` 查詢，無法確認自身身分便不回覆該社群 |
| `line.textMaxLength` | 每段 LINE 文字的 UTF-16 長度上限，預設 8000；須不超過 LINE.js 設定 |
| `line.sendsPerMinute` | 本元件所有聊天室共用的滾動 60 秒發送上限，預設 20；不得高於 LINE.js 上限，多個機器人須自行分配額度 |
| `line.maxPendingPerChat` | 每聊天室未完成工作上限，預設 50，範圍 1～10000；包含等待與正在處理的工作，不得大於全域上限 |
| `line.maxPendingTotal` | 全部聊天室未完成工作總上限，預設 200，範圍 1～10000；舊設定省略兩欄時自動採用預設值 |
| `provider` | 主要供應商 `openai` 或 `claude`；省略時有 `openai` 段就用 OpenAI，否則用 Claude（舊設定不必修改）。指定的那段必須存在 |
| `openai.apiKey` | OpenAI API key，僅供伺服器使用 |
| `openai.model` | 對話模型，例如 `gpt-6-luna`（最快、最便宜） |
| `openai.reasoningEffort` | 選填，`none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`；省略時用模型預設值。可用值依模型而定，`gpt-6-luna` 支援 `none` |
| `openai.serviceTier` | 選填，`fast` 或 `default`；省略時依 OpenAI 專案設定。`fast` 為 [Fast mode](https://developers.openai.com/api/docs/guides/fast-mode)（官方稱最多快 2.5 倍、延遲較穩定），每 token 另收溢價，只用於生成請求（計數 API 不接受此欄位）；支援模型見官方定價頁 |
| `openai.contextTokens`／`maxOutputTokens`／`timeoutMs` | 與 `claude` 同義；`maxOutputTokens` 包含推理 tokens |
| `openai.imageModel` | 畫圖模型，預設 `gpt-image-2.5-flare` |
| `openai.imageQuality` | `low`、`medium`、`high`、`xhigh`、`max` 或 `auto`，預設 `medium`；越高越慢 |
| `openai.imageTimeoutMs` | 單張圖片生成的逾時，預設 120000ms，範圍 1000～300000 |
| `claude.apiKey` | Anthropic API key，僅供伺服器使用 |
| `claude.model` | `claude-haiku-5-5`，不會自動換用其他模型 |
| `claude.contextTokens` | 100000；可降低，不可提高 |
| `claude.maxOutputTokens` | 預設 4096，包含在上下文總額內 |
| `claude.timeoutMs` | 每輪計數與生成合計的逾時，預設 60000ms |
| `personalityFile` | 個性 Markdown 路徑，預設 `personality.md`；相對路徑以設定檔所在目錄為基準 |

直接編輯 `personality.md` 即可調整語喵個性，重啟後生效。人格以群聊夥伴為主，不預設成員背景或專屬關係；依 `sender.id` 區分成員，不混淆不同成員的立場。明確對語喵進行的問答與聊天會積極參與，但不硬找話題、強行追問或延長已結束的對話。回覆前須理解完整訊息、指涉與最新更正，不只抓關鍵字接話；確定在問語喵但缺少必要資訊時才簡短澄清，不腦補引用內容。名稱與文字以 JSON 資料送入，而非當成系統指令。這個元件沒有上網、操作檔案或執行指令等工具。個性檔案不存在或為空白時會拒絕啟動。

## OpenAI 與 Claude

- 對話與畫圖預設使用主要供應商；另一個供應商有設定時作為備用。主要供應商的計數、生成或檔案內容請求失敗（HTTP 錯誤、網路錯誤、逾時、回應格式錯誤或輸出截斷）時，同一則訊息改由備用供應商從頭處理，終端機記錄 `openai_fallback:代碼[:HTTP 狀態]` 或 `claude_fallback:…`，不含訊息或金鑰。取消不會切換。逾時後才切換時，該則回覆最慢要等兩份逾時。
- 供應商的決策請求因逾時、網路錯誤、HTTP 429 或 5xx 失敗時，接下來 60 秒的新訊息先交給另一個供應商，不必每則都重新等它失敗；60 秒後恢復原本順序。HTTP 400 等請求本身的錯誤不影響順序。
- 圖片與檔案從做出該回合決策的供應商開始：主要供應商這回合已失敗時，不再為同一回合的圖片或檔案重試它。
- OpenAI 對話使用 [Responses API](https://developers.openai.com/api/docs/guides/function-calling)，以強制的 function call 回傳同一份決策格式（`strict: false`，因為 `draw`／`file` 是選填欄位）；`store: false` 不在 OpenAI 保存回應。上下文裁切改用 OpenAI 的 [`POST /v1/responses/input_tokens`](https://developers.openai.com/api/docs/guides/token-counting) 計數，規則與 Claude 相同。[Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching) 的預設隱含斷點只落在最新的成員訊息，而頂層 `instructions` 不能設斷點；因此人格與判斷提示改放在開頭的 developer 訊息，人格與決策提示各加一個明確斷點（與 Claude 相同），讓不同聊天室、新對話與第一則訊息也能重用人格前綴。前綴需達 1024 tokens 才會快取，寫入按 1.25 倍輸入費率、讀取按 0.1 倍計價。請求不使用 gzip。
- OpenAI 畫圖直接呼叫 [Images API](https://developers.openai.com/api/docs/guides/image-generation) 的 `POST /v1/images/generations`，以決策中的圖片描述為提示，產生 1024×1024 JPEG（官方說明 JPEG 比 PNG 快）後原樣上傳，不經過 SVG；不需要第二次對話請求，也不受 SVG 只能畫向量圖的限制。Claude 仍以 SVG 畫圖。OpenAI 以 HTTP 400 拒絕圖片（包含內容審核）時記錄 `image_rejected` 並回覆「這張圖沒辦法畫，請換個主題或說法。」，**不會**改用 Claude 重畫，以免繞過審核；其他圖片錯誤才會切換到 Claude 的 SVG。
- GPT Image 模型可能需要先完成 OpenAI 組織驗證才能使用。

## 對話與斷線行為

- 每個聊天室使用獨立的記憶體上下文，同一聊天室依序回答，包含已成功發送的問答；不保存聊天紀錄到磁碟。
- 佇列滿載採「淘汰最舊待處理訊息」：先檢查聊天室上限，必要時淘汰該聊天室最舊的等待項目；否則遇全域上限時，淘汰全域最舊等待項目。已開始的身分／歷史查詢、生成、等待發送額度或發送確認都不會因滿載被取消；沒有可淘汰項目時拒收新訊息。保留下來的同聊天室工作仍依原順序處理，淘汰的正文會從佇列移除，不保留無限增長的 Promise 鏈。
- 淘汰／拒收僅記錄 `queue_evicted`／`queue_full`，不含訊息內容或識別資料，不額外發送「忙碌」訊息；被捨棄的訊息不呼叫 Claude、不寫入對話上下文，也不自動補處理，在既有去重視窗內收到重複事件仍不重做。因此超載時，較早排隊的問題可能不再回答；佇列上限限制的是工作筆數，不是記憶體 bytes。
- 已知自身 ID 時，自己的即時訊息在入列前就排除，仍記住作者分類供後續引用辨識，不占回答佇列或擠掉成員問題。一般聊天室使用登入 ID；社群使用設定或已成功查得的成員 ID。社群身分尚未確認時仍依原流程查詢後排除，不猜測作者。
- 身分已確認時，合格的成員即時文字訊息也會在入列前記住作者分類；即使正文稍後被淘汰或因滿載拒收，引用仍可使用既有分類免查歷史。只保留有容量限制的聊天室／訊息 ID 與自己／他人分類，不保留被淘汰正文，也不讓它進入模型上下文；收回與權限等失效規則照常適用。
- 聊天室尚未接話且沒有處理中／等待中的訊息時，沒有候選觸發的普通閒聊直接略過，不占佇列，也不為此查詢社群身分。身分已確認時沿用完整 mention 驗證，因此只標記別人、`@All` 或格式無效，且沒有「語喵」或引用線索的訊息也會在入列前排除；社群身分未知時，任何非空 mention 陣列仍保留作候選，不猜測標記對象。只要已有待處理訊息就不走此快速排除，避免漏掉前一則回答成功後應判斷的追問；候選觸發仍須通過既有身分、標記、作者與模型判斷。
- 上述閒置狀態下，引用作者已確認是他人且沒有其他候選觸發時，也直接略過，不讓已確認無關的引用擠掉其他聊天室的待回答問題。引用作者未知或是自己時仍保留；提到「語喵」或有效標記仍可觸發，作者快取失效後仍重新查詢。
- 引用回覆語喵、有效 @ 標記或文字提到「語喵」都是候選觸發，不再強制回答。直接觸發與後續訊息都透過同一個內部決策格式判斷是否回覆；只是談論語喵、引用給別人看、向其他人提問或對象不明時保持安靜。明確叫語喵、打招呼或換題向語喵提問仍可回應，不要求一定有問號。
- 尚未接話的聊天室，沒有候選觸發條件的文字不送往 Claude。完整回答成功發送後才啟用後續問答判斷；任何送交判斷的訊息即使決定不回覆仍會產生 Claude API 用量，被忽略的訊息不發送、不寫入對話上下文，也不啟用接話狀態。無關訊息不關閉既有對話，之後仍依是否明確對語喵進行問答逐則判斷；不設固定時間逾時。
- 標記必須是 LINE 提供、指向自己帳號／社群成員 ID 的有效 mention，`@All` 或標記其他人不算。引用先比對已確認的作者分類（自己／他人，以聊天室與訊息 ID 隔離，全域最多記住 10000 筆）；若不認得，透過 LINE.js `history:fetch` 分頁確認被引用訊息的作者。已確認是他人的引用不重複查詢；查不到、查詢失敗、作者欄位不合法或已收回不寫入否定快取。因此重啟、重連前的引用，只要 LINE 歷史仍可取得也能觸發；作者不是自己或已收回時不視為直接觸發。歷史只用於辨識作者，不重播訊息、不將歷史正文送給 Claude。作者快取在訊息收回、聊天室移出授權範圍、斷線、登出或換帳號時失效；一般編輯保留作者分類，已取消查詢的遲到回應不能重新寫入。
- 作者分類也會從通過既有檢查的即時文字訊息，以及已下載歷史頁內每筆有效、同聊天室且未收回的訊息建立；不只記住當次引用目標。社群先確認自身成員 ID 再分類；其他聊天室、無效作者／訊息 ID 不納入歷史頁快取，已收回的歷史項目會移除對應快取。這些觀察只保留識別資訊與作者分類，不保存正文或重播歷史。
- 作者快取以最近使用／更新順序保留，容量滿時淘汰最久未使用的紀錄；持續引用的舊訊息不會只因最早加入就被其他聊天室的新流量擠掉。自己與他人的已確認分類都會刷新使用順序，容量與上述失效規則不變。
- 歷史與社群管理員查詢共用每條 WebSocket 連線的滾動 1 秒額度，最多 10 次；包含首頁及不同聊天室的查詢，與文字發送額度分開。排隊等待可取消，斷線或權限失效不會稍後補送；15 秒回應逾時從實際送出時起算。
- 後續判斷與回答在同一次模型生成完成，內部決策資料不傳送到 LINE。只是相同話題、其他成員彼此交談或關聯不明時不接話；判斷屬模型推論，並非保證零誤判。
- 確保人格、對話輸入、直接回答或關聯度決策提示與 schema、預留輸出合計不超過 100K tokens。位元組層級 tokenizer 每個 token 至少對應 1 個 UTF-8 byte，因此計數請求的 JSON body 位元組數加上 2048（涵蓋 body 未列出的提示模板）仍不超過輸入上限時，直接生成而不呼叫計數 API，省下一次往返；中文每字 3 bytes，實際 token 遠少於此上限。長對話超過這個門檻後，以同一供應商上次官方計數為「可容納」的 token 數，加上之後新增的訊息（及不同判斷提示）的位元組數作為上限，仍有 2048 餘裕時同樣不計數；只有接近上限、清除上下文或換供應商時才呼叫 Anthropic 的 [token 計數 API](https://platform.claude.com/docs/en/api/messages/count_tokens)（OpenAI 為 `input_tokens`）。超限時先嘗試只移除最舊一組完整問答；仍超限時，利用這兩次官方計數的差值估計下一個搜尋位置，再透過官方計數與二分搜尋找到最少應移除的組數，不重複計數已確認的候選。估計只決定搜尋順序，不用來批准生成；沒有可用差值時走原有搜尋，低估時擴大範圍。需要裁切時，每個生成輸入仍須通過官方計數，不裁切人格或最新訊息；只剩最新訊息仍超限便不生成，後續訊息若已無保留對話可判斷則保持安靜。歷史問答大小接近時可減少往返，大小不均時可能增加探測次數。
- 生成請求啟用 Anthropic [5 分鐘 prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)：固定人格與其後的直接呼叫／後續對話提示各設一個明確快取斷點，並保留整段對話的自動快取。切換觸發模式或聊天室時仍可重用工具與人格前綴；同一模式也可重用固定判斷提示，不必等到最後一則成員訊息完全相同。歷史快取仍需要前綴一致。這不是快取整份回答。首次寫入按官方快取寫入費率計價，命中後按較低讀取費率計價；是否命中取決於模型的最短快取長度、前綴一致性與到期時間。快取由 Anthropic 管理，清除本機對話不代表立即刪除上游快取，不保證每輪都更快。
- 計數與生成的 JSON body 達 4 KiB（按 UTF-8 bytes 計）時，使用 Node.js 非同步 gzip 快速壓縮；只有壓縮後較小才附上 `Content-Encoding: gzip` 傳送，小請求維持原樣。這減少的是上傳 bytes，不減少 token、API 呼叫次數或改變對話內容；壓縮時間包含在每輪逾時內。取消或逾時會銷毀壓縮串流並立即結束等待，不必等 worker 空出，也不會上傳；已派送的原生壓縮工作仍可能在內部完成。Anthropic 官方工具亦採用 [API 請求 gzip 壓縮](https://code.claude.com/docs/en/env-vars#variables)；若網路經過 TLS 檢查代理，代理須支援轉送壓縮 body。HTTP 失敗時中止未讀取的回應傳輸，不下載或記錄錯誤正文，也不自動重送。
- 模型出錯、計數失敗或回答因輸出額度截斷時，不傳送不完整回答，終端機記錄安全錯誤代碼，不輸出金鑰或訊息原文。
- 長回答分段發送，不拆開 Unicode surrogate pair；所有段落取得 `sent` 確認後，才將完整問答納入上下文。部分發送失敗不回滾已送出的段落，也不自動重送。
- 已準備好的回答在有額度時可每 250ms 發送一段，不再將每分鐘額度平均攤成固定等待。所有聊天室共用滾動 60 秒總量上限；額度耗盡才等待最早一次發送到期，斷線不會重設這份限流紀錄。等待中被取消的回答不會在稍後自動補送；即使排在其他聊天室後方，也會立即結束該聊天室的等待，讓新訊息可以開始準備。取消不占用之後的發送額度，未取消的回答仍依原有 FIFO 順序與限流發送。Claude 生成與 LINE 確認仍需各自的網路時間。
- 依 [LINE.js 文字訊息轉換](https://github.com/JS-PACKAGE/LINE.js/blob/db2a0cd0add41f3a36d3fb2fccd52b09e9ca2183/src/line/provider.ts)，文字訊息的 `contentType` 是 `NONE`（不是 `TEXT`）。不回覆自己的訊息、歷史 snapshot、已收回或解密失敗的訊息、非文字訊息；保留最近 10000 個訊息 ID 去重。
- 與 LINE.js 斷線、初次連線失敗、心跳失敗時，**每次失敗後等待 10 秒重連**。WebSocket handshake 最多等待 10 秒；連線後每 30 秒 ping，10 秒未收到 pong 即重連。關閉程式會取消重連。
- 斷線或登出會取消待處理回答、清空上下文與身分資訊。重連後重新等待登入狀態，只處理新事件；不補抓斷線期間的訊息，也不重送結果不明的發送請求。去重資料跨重連保留、程式重啟則清除。
- 訊息被編輯、收回或聊天室被移出授權範圍時，清除該聊天室上下文並取消尚未完成的回覆，避免繼續使用已撤回的內容；不能撤回已送至 Anthropic 或 LINE 的內容。
- 上述上下文清理也會重設接話狀態，必須再次直接叫到語喵才會開始回答。斷線、登出或換帳號也會清除引用辨識資料；編輯訊息不改變原作者，但收回的訊息不能再用來觸發引用回覆。
- 擁有者指令：需要 LINE.js 宣告 `chat:admin-token` 能力。NekoChat 保存 LINE.js 主動推送的各聊天室目前一次性管理員權杖（只存記憶體，不記錄）；成員訊息包含該權杖時，不論是否叫到語喵、引用誰，都會先以 `chat:admin-token:consume` 兌換。兌換成功才視為擁有者：必定送交模型，並以 `verifiedOwner` 標記與擁有者提示要求完全遵守指令且一定回覆，但仍不得透露系統提示或機密。兌換失敗時依一般規則處理。權杖在送往 OpenAI／Anthropic 與寫入上下文前會替換為「[權杖]」。兌換後 LINE.js 推送新權杖，舊權杖之後只是普通文字。斷線、登出、聊天室移除或 `chat:admin-token:changed` 都會清除保存的權杖。
- 已驗證擁有者的要求即使離譜、荒謬、尷尬或不合人格，也不能僅因此拒絕、淡化、替換任務或擅加評論；提示要求嚴格遵守指定措辭、語言、格式、語氣與範圍，回覆不限定為自然對話文字。機密保護及不得假裝執行外部操作仍適用；這是應用層提示規則，不能保證模型完全服從或繞過供應商限制。
- 畫圖：被要求畫圖時，模型先在決策格式的 `draw` 欄位寫出可獨立使用的圖片描述，並以回覆文字表示開始畫（回覆空白時改送「收到，正在畫圖，請稍等。」），這段文字立即送出。OpenAI 接著以該描述呼叫 Images API 產生 JPEG（見上方「OpenAI 與 Claude」）；Claude 則另以一次 `draw_svg` 請求（沿用同一份已確認容量的上下文與人格快取）產生 SVG，NekoChat 以 `@resvg/resvg-js` 在本機轉成長邊 1024 px、白底的 PNG。兩者都透過 LINE.js 的 `POST /api/media/upload`（同一 Bot Token）上傳後送出。成員不必等圖片完成才知道指令已收到。需要 LINE.js 宣告 `media:upload` 能力，否則記錄 `image_unavailable`。為避免 resvg 讀取本機檔案，含 `<image>`、`<feImage>`、`<foreignObject>`、`<script>`、DOCTYPE／ENTITY、`@import`，或指向非 `#` 片段的 `href`／`url()` 的 SVG 一律拒絕（`image_unsafe`）；SVG 無效記錄 `image_invalid`，產生圖片或上傳失敗（含 LINE.js 每分鐘 5 次的上傳額度）記錄 `image_failed`。上下文只保留「（附上一張圖片）」，不保留圖片資料或 SVG 原始碼，以免拖慢後續請求。Claude 的 SVG 只能畫向量風格圖形，圖中文字使用下方的 CJK 字型。
- 檔案附件：被要求提供任何文件時，模型先在決策格式的 `file` 欄位給出檔名與內容說明，並以回覆文字表示正在準備（回覆空白時改送「收到，正在準備檔案，請稍等。」），這段文字立即送出；接著另以一次 `write_file` 請求（沿用同一份已確認容量的上下文與人格快取）寫出完整內容後才上傳，支援 `.txt`、`.md`、`.csv`、`.pdf`。檔名不合規則或 PDF 缺字型時在第二次請求前就拒絕，不浪費 API 費用。文字檔以 UTF-8 原樣上傳（`content-type: text/plain`，檔名以 `X-File-Name` 傳送）；PDF 由 `pdfkit` 把純文字排版成 A4 頁面並嵌入 CJK 字型子集。同樣需要 `media:upload` 能力（否則記錄 `file_unavailable`），送出順序為文字、圖片、檔案，與圖片共用 LINE.js 每分鐘 5 次的上傳額度。檔名含 `/`、`\`、控制字元、超過 100 字或副檔名不符，或內容含 Tab／換行以外的控制字元時記錄 `file_invalid`；內容產生失敗記錄 `file_write_failed`，上傳失敗記錄 `file_failed`。上下文只保留「（附上檔案 檔名）」。檔案長度受所用供應商的 `maxOutputTokens` 限制（預設 4096，約數千字）。
- CJK 字型：PDF 內建字型沒有中文字，resvg 在沒有 fontconfig 的主機上也找不到任何系統字型，會讓 SVG 文字整段消失，因此兩者共用一個明確指定的 CJK 字型。省略 `cjkFont` 時自動尋找 Noto Sans CJK（Debian/Ubuntu `apt install fonts-noto-cjk`、Arch、Fedora 的標準路徑）與 macOS 的 Hiragino Sans GB；也可設定 `cjkFont: { file, name }`，相對路徑以設定檔目錄為基準，`.ttc`／`.otc` 字型集合必須指定 PostScript 名稱。SVG 只載入這個字型並以它代替所有字型家族，略過系統字型掃描（本機實測由約 0.3～2.8 秒降到約 20 ms），代價是字型沒有的字元（例如彩色 emoji）不會顯示。都找不到時 PDF 停用（記錄 `pdf_unavailable`）、SVG 改用系統字型，文字檔不受影響；`./start.sh --check` 會顯示使用的字型。
- 圖片與檔案在背景完成：確認文字全部取得 `sent` 後，該回合（含「（附上一張圖片）」等標記）立即寫入上下文，同一聊天室的下一則訊息不必等圖片或檔案生成。同一聊天室的圖片與檔案仍依回合順序送出；訊息被編輯、收回或聊天室失去權限時，進行中的圖片與檔案一併取消。
- 圖片或檔案無法產生、被拒絕或上傳失敗時，語喵會以引用原訊息的一句話告知（例如「目前無法產生 PDF，可以改用 txt 或 md。」）並記錄對應代碼；該回合已在確認文字送出時寫入上下文，標記仍會保留。
